# 요구사항 및 구현 범위

명세서의 Servlet/JSP MVC 구조와 필수 기능을 우선 구현하고 선택 기능을 추가했습니다.

| 번호 | 구분 | 구현 및 확인 방법 |
| --- | --- | --- |
| F101 | 필수 | TourAPI `areaBasedList2`, 지역/시군구 조회, 목록·사진·상세 화면 |
| F102 | 필수 | 관광지(12), 숙박(32), 음식점(39) 필터 |
| F103 | 필수 | 문화시설(14), 공연(15), 여행코스(25), 쇼핑(38), 레포츠(28) 필터 |
| F104 | 추가 | 기간·예산·일차·경비·메모·여행지 저장, 방문 순서 변경, 위치·동선 지도 |
| F105 | 추가 | 사진·방문일·유형·설명·위치 저장, 지도 클릭 위치 선택, 갤러리 |
| F106 | 심화 | Google 뉴스의 관광·여행 RSS 수집, 제목/출처/원문 URL 저장·중복 제거·조회 |
| F107 | 필수 | 회원 가입·본인 조회·수정·비밀번호 확인 후 탈퇴 |
| F108 | 필수 | 로그인·세션 회전·POST 로그아웃·15분/1회용 토큰 재설정·SMTP 안내 |
| F109 | 심화 | 공지사항 CRUD, 설정에 등록된 관리자만 작성/수정/삭제 |
| F110 | 심화 | 공유게시판 CRUD, 본인 또는 관리자만 수정/삭제 |
| F111 | 선택 아이디어 | 기간별 날씨: 미구현 |
| F112 | 선택 아이디어 | 별도 추천 사진: 미구현 (기본 관광지 사진은 F101에서 제공) |
| F113 | 선택 아이디어 | 일출·일몰: 미구현 |
| F114 | 선택 아이디어 | 충전소 위치·상태: 미구현 |

## 비기능 요구사항

- NF101·NF102: 반응형 JSP, 명시적 입력 라벨, 오류 안내, 드래그 대신 위/아래 버튼도 제공
- NF103: 관광지 목록 Redis 캐시(TTL 기본 600초), 조건 전체를 키에 반영, 연결 실패 시 원본 조회
- NF104: live 모드의 관광 정보는 한국관광공사 데이터 사용. 샘플은 demo 모드에서만 명시적으로 표시

## 구현 선택

- MySQL 운영 연결 외에 자격 증명 없는 개발/검증을 위한 H2 demo 모드를 제공합니다.
- 지도 API 키 없이 검증할 수 있도록 Leaflet/OpenStreetMap을 사용합니다. 방문 순서의 연결선이며 도로 길찾기/소요 시간 계산은 포함하지 않습니다.
- F106은 RSS 기반 수집이며 기사 본문을 크롤링/복제하지 않습니다. 관리자 수동 실행, 5분 간격 제한입니다.
- 로그인은 Tomcat HttpSession을 사용합니다. Redis 세션 클러스터링은 포함하지 않고 관광지 캐싱에 집중했습니다.
- 기존 비밀번호 조회 대신 이메일을 통한 비밀번호 재설정으로 F108을 구현했습니다.
- 사진은 웹 루트 밖에 저장하고 JPEG로 재인코딩합니다. 별도 사진 수정/삭제 UI는 포함하지 않으며 탈퇴 시 함께 삭제합니다.

실제 TourAPI 키/SMTP 자격 증명은 개인 파일에 설정해야 합니다. 외부 지도 타일·뉴스·메일 서비스의 네트워크 가용성은 별도 운영 환경에서 확인합니다.
